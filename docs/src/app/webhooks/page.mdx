# Webhooks

Webhooks allow you to receive real-time HTTP notifications when events happen during verification sessions. Rather than polling the API, webhooks push data to your endpoint as soon as events occur. {{ className: 'lead' }}

## Overview {{ anchor: false }}

FaceSign sends webhook events for session status changes, media uploads (photos, videos), and AI analysis results. Configure your webhook endpoint in the FaceSign Dashboard to start receiving events.

<Note>
  Dev environment webhooks currently use basic authentication. Signature-based verification may be added in the future. See [Signed Headers](/webhooks/signed-headers) for the proposed implementation.
</Note>

## Webhook events

FaceSign sends the following webhook event types:

<Row>
  <Col>

### Session Events

<Properties>
  <Property name="session.status" type="event">

  </Property>

### Media Events

<Properties>
  <Property name="media.user_photo" type="event">
    Sent when a user photo is captured (e.g., during face scan or liveness detection). Includes a signed URL to download the image.
  </Property>
  <Property name="media.document_photo" type="event">
    Sent when a document photo is captured during document scanning. Includes a signed URL to download the image.
  </Property>
  <Property name="media.user_video" type="event">
    Sent when user video is recorded. Includes a signed URL to download the video file.
  </Property>
</Properties>

### Analysis Events

<Properties>
  <Property name="analysis.video" type="event">
    Sent when AI video analysis completes (if `videoAIAnalysisEnabled: true`). Includes behavioral insights and fraud detection signals.
  </Property>
  <Property name="analysis.screenshot" type="event">
    Sent when AI screenshot analysis completes. Includes analysis results and confidence scores.
  </Property>
</Properties>

### Settings Events

<Properties>
  <Property name="settings.avatars" type="event">
    Sent when avatar settings change. Includes updated avatar configuration.
  </Property>
  <Property name="settings.langs" type="event">

## Setting up webhooks

Configure webhooks in three steps: create an endpoint, register it in the FaceSign Dashboard, and handle incoming events.

<Row>
  <Col>

### 1. Create an endpoint

Your webhook endpoint should:

- Accept POST requests with JSON payloads
- Respond quickly with a 2xx status code
- Process events asynchronously (use a queue for time-consuming operations)
- Validate events by fetching the session from the API

<Note>
  Dev environment does not include signature headers yet. Validate events by fetching the session and checking `clientReferenceId` or metadata.
</Note>

### 2. Register your endpoint

Go to the FaceSign Dashboard → Settings → Webhooks and add your endpoint URL.

### 3. Handle events

Process events based on their type and take appropriate actions in your application.

## Event object structure

All webhook events share a common structure with event-specific data.

<Row>
  <Col>

### Common Fields

<Properties>
  <Property name="id" type="string">
    Unique event identifier. Use for idempotency (prevent duplicate processing).
  </Property>
  <Property name="type" type="string">
    Event type (e.g., `"session.status"`, `"media.user_photo"`).
  </Property>
  <Property name="createdAt" type="number">
    Unix timestamp when the event was created.
  </Property>
  <Property name="sessionId" type="string">
    ID of the session this event relates to.
  </Property>
  <Property name="media" type="object" nullable>
    Media object with signed URL (only for media and analysis events).
  </Property>
</Properties>

### Media Object (when present)

<Properties>
  <Property name="id" type="string">
    Media identifier.
  </Property>
  <Property name="createdAt" type="number">
    Unix timestamp when media was created.
  </Property>
  <Property name="url" type="string">
    Signed URL to download the media (expires after `expires` timestamp).
  </Property>
  <Property name="expires" type="number">
    Unix timestamp when the signed URL expires (typically 15 minutes).
  </Property>
  <Property name="contentType" type="string">
    MIME type (e.g., `"image/jpeg"`, `"video/mp4"`, `"application/json"`).
  </Property>
</Properties>

## Handling webhooks

### Common Use Cases

<Row>
  <Col>

**Session Status Changes**

Monitor verification progress and update your database when sessions complete:

```javascript {{ title: 'Handle Session Status' }}
async function handleSessionStatus(event) {
  const { sessionId } = event

  // Fetch full session details
  const { session } = await client.session.retrieve({ sessionId })

  if (session.status === 'complete') {
    // Update user verification status in your database
    await db.users.update({
      where: { id: session.settings.clientReferenceId },
      data: {
        verificationStatus: 'verified',
        verifiedAt: new Date(),
        sessionId: session.id
      }
    })
  }
}
```

**Media Downloads**

Download and store user photos and videos:

```javascript {{ title: 'Handle Media Event' }}
async function handleUserPhoto(event) {
  const { media, sessionId } = event

  if (!media?.url) return

  // Download photo from signed URL
  const response = await fetch(media.url)
  const buffer = await response.arrayBuffer()

  // Store in your system
  await storage.save(\`sessions/\${sessionId}/photo.jpg\`, buffer)
}
```

  </Col>

**Video AI Analysis**

Process AI analysis results for fraud detection:

```javascript {{ title: 'Handle Analysis Event' }}
async function handleVideoAnalysis(event) {
  const { media, sessionId } = event

  if (!media?.url) return

  // Download analysis JSON
  const response = await fetch(media.url)
  const analysis = await response.json()

  // Check fraud signals
  if (analysis.fraudScore > 0.8) {
    await alerts.send({
      type: 'HIGH_FRAUD_RISK',
      sessionId,
      score: analysis.fraudScore,
      signals: analysis.signals
    })
  }
}
```

## Best practices

### Reliability

1. **Respond quickly** - Return 2xx status within 5 seconds. Process work asynchronously.
2. **Handle duplicates** - Use `event.id` to ensure idempotent processing.
3. **Verify events** - Always fetch the session to validate webhook authenticity.
4. **Implement retries** - FaceSign retries failed deliveries with exponential backoff.

### Security

1. **Use HTTPS** - Only register HTTPS endpoints (required for production).
2. **Validate sessions** - Fetch session by ID and check your `clientReferenceId` or metadata.
3. **IP allowlisting** - Optionally restrict requests to FaceSign IP addresses.
4. **Monitor for anomalies** - Track unusual patterns in webhook traffic.

### Performance

1. **Use queues** - Offload processing to background workers.
2. **Download media quickly** - Signed URLs expire in 15 minutes.
3. **Scale horizontally** - Webhook endpoints should be stateless.
4. **Cache session data** - Reduce API calls by caching session information.

<Note>
  FaceSign retries failed webhooks (non-2xx responses) up to 5 times with exponential backoff: 5s, 30s, 2m, 10m, 1h.
</Note>
