## What is Flow Designer?

Flow Designer is a **visual design and testing tool** for creating identity verification workflows. It runs in the FaceSign Sandbox environment and is intended for:

- ✅ **Prototyping** verification flows
- ✅ **Testing** flow logic with sample data
- ✅ **Creating demos** for stakeholders
- ❌ **NOT for production use**
- ❌ **NOT for real user data or PII**

## Getting Access

To use Flow Designer, you need access to the FaceSign Sandbox:

1. **Request Access**: Contact your FaceSign administrator for provisioning
2. **Receive Credentials**: You'll get access to the Sandbox environment
3. **Access Flow Designer**: Navigate to https://create.facesign.ai
4. **Find Your API Key**: Once logged in, go to Settings → API Keys

Your Sandbox API key will look like: `sk_test_...`

## Creating Flows Visually

Flow Designer provides a drag-and-drop interface for building verification flows:

### Node Library

The left panel contains all available verification nodes:

- **Start/End**: Required entry and exit points
- **Conversation**: AI-powered conversational interactions
- **Document Scan**: Identity document verification
- **Liveness Detection**: Anti-spoofing checks
- **Email Entry**: Email collection and verification
- **Face Scan**: Facial recognition/matching
- **Two Factor**: SMS/Email OTP verification
- **Data Validation**: Conditional logic nodes

## Exporting Flows (BETA)

Once you've designed and tested your flow, you can export it for use with the production API:

### Export Process

1. Open your tested flow in Flow Designer
2. Click the **Export** button in the toolbar
3. Choose export format (currently JSON only)
4. Copy the exported configuration

## Next Steps: Implement with the API

After designing and exporting your flow, implement it in your application:

### 1. Install the SDK

### 2. Use Your Exported Flow

<SimpleCodeBlock
  title="Implement in Production"
  language="javascript"
  code={`import { Client } from '@facesignai/api'
import flowConfig from './exported-flow.json'

const client = new Client({
  auth: process.env.FACESIGN_LIVE_KEY, // Production key: sk_live_...
  serverUrl: 'https://api.facesign.ai'
})

// Create a session with your exported flow
const { session, clientSecret } = await client.session.create({
  clientReferenceId: userId,
  metadata: { source: 'onboarding' },
  flow: flowConfig  // Your exported flow configuration
})

// Direct user to verification
console.log('Verification URL:', clientSecret.url)`}
/>

### 3. Handle Production Data

Remember the key difference:

- **Sandbox (Flow Designer)**: Test data only, no PII
- **Production (Your App)**: Real user data, full security

## Common Flow Patterns

Here are some common verification flow patterns you can create in Flow Designer:

### Basic KYC Flow
```
Start → Email → Document Scan → Liveness → End
```

### Enhanced Verification
```
Start → Email → Document → Face Match → Two Factor → End
```

### Progressive Verification
```
Start → Email → Data Validation → (if high risk) → Document → End
                                 → (if low risk) → End
```

## Limitations and Considerations

### Sandbox Limitations

- **Rate limits**: Lower than production
- **Data retention**: Test data cleared regularly
- **Features**: Some production features may not be available
- **Performance**: Not representative of production performance

### Production Considerations

When moving to production:

- Implement proper error handling
- Add monitoring and logging
- Set up webhook handlers
- Configure retry logic
- Plan for scale
