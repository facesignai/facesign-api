# Authentication

The FaceSign API uses API keys to authenticate requests. You can view and manage your API keys in the FaceSign Dashboard. {{ className: 'lead' }}

## API Keys

FaceSign provides two types of API keys:

- **Test mode keys** - Start with `sk_test_` and can be used for development and testing
- **Production mode keys** - Start with `sk_live_` and should be used in your production environment

<Note>
  Test mode keys have the same capabilities as production keys but will not charge your account. All sessions created in test mode are clearly marked.
</Note>

## Getting your API keys

1. Log in to your FaceSign Dashboard
2. Navigate to **Settings** → **API Keys**
3. Copy your API key for the appropriate environment

<Warning>
  Keep your API keys secure! Never commit them to version control or expose them in client-side code.
</Warning>

## Using API keys

Include your API key in the `Authorization` header of every request:

<CodeGroup>

```bash {{ title: 'cURL' }}
curl https://api.dev.facesign.ai/sessions \
  -H "Authorization: Bearer sk_test_4eC39HqLyjWDarjtT1zdp7dc"
```

```typescript {{ title: 'TypeScript' }}
import Client from '@facesignai/api'

const client = new Client({
  auth: 'sk_test_4eC39HqLyjWDarjtT1zdp7dc',
  serverUrl: 'https://api.dev.facesign.ai'
})
```

```python {{ title: 'Python' }}
import facesignai

client = facesignai.Client(
    auth='sk_test_4eC39HqLyjWDarjtT1zdp7dc',
    base_url='https://api.dev.facesign.ai'
)
```

</CodeGroup>

We strongly recommend using environment variables to store your API keys:

<CodeGroup>

```bash {{ title: '.env' }}

```

import Client from '@facesignai/api'

```

    base_url='https://api.dev.facesign.ai'

```

## Client-side authentication

**Never use your API key on the client side!** Instead, create a session on your backend and provide the client secret URL to your end users:

```typescript {{ title: 'Backend: Create session and get client secret' }}
import Client from '@facesignai/api'

const client = new Client({
  auth: process.env.FACESIGN_API_KEY,
  serverUrl: 'https://api.dev.facesign.ai'
})

const { session, clientSecret } = await client.session.create({
  clientReferenceId: 'user-123',
  metadata: {},
  flow: { nodes: [...], edges: [...] }
})

// Client secret format: csea61d44d88d345e1b91622820bb73100
// URL format: https://session.dev.facesign.ai?cs=csea61d44d88d345e1b91622820bb73100

// Redirect user to clientSecret.url
res.redirect(clientSecret.url)
```

The client secret is embedded in the session URL. Your end user navigates to `clientSecret.url` to begin verification. Client secrets expire after 2 hours by default.

## Rate limiting

API requests are rate limited to ensure fair usage:

- **Test mode**: 100 requests per minute
- **Production mode**: 1000 requests per minute

If you exceed the rate limit, you'll receive a `429 Too Many Requests` response:

```json {{ title: 'Rate limit error' }}
{
  "error": {
    "type": "rate_limit_error",
    "message": "Too many requests. Please retry after 60 seconds."
  }
}
```

## API versioning

The FaceSign API uses date-based versioning. The SDK automatically sends the `Facesign-Version` header with each request:

```bash {{ title: 'API version header (sent automatically by SDK)' }}
curl https://api.dev.facesign.ai/sessions \
  -H "Authorization: Bearer sk_test_..." \
  -H "Facesign-Version: 2024-12-18"
```

<Note>
  The SDK uses version `2024-12-18` by default. This header is automatically included in all SDK requests.
</Note>

<CollapsibleSection title="Security Best Practices" variant="subtle">

1. **Never expose your API keys** - Keep them server-side only
2. **Use environment variables** - Don't hardcode keys in your source code
3. **Rotate keys regularly** - Generate new keys periodically
4. **Use test keys for development** - Keep production keys secure
5. **Monitor key usage** - Check your dashboard for unusual activity

<Warning>
  API keys provide complete access to your FaceSign account. Treat them like passwords and keep them secure.
</Warning>

</CollapsibleSection>

## Webhook security

FaceSign sends webhook events for session updates and media uploads. Currently, Dev environment webhooks use basic validation - you should verify events by fetching the session via API and checking your `clientReferenceId` or metadata.

See [Webhooks](/webhooks) for complete documentation on event types and handling.

<Note>
  Signature-based webhook verification is planned for future releases. For now, validate events by fetching the session from the API.
</Note>
