# Custom Flows

Build sophisticated verification experiences with FaceSign's node-based flow system. Create conditional verification paths, implement complex business logic, and design user experiences that adapt to different scenarios. {{ className: 'lead' }}

## Overview {{ anchor: false }}

While the verification modules provide a simple way to configure common verification patterns, custom flows give you complete control over the verification process. Flows are built using a node-graph system where:

- **Nodes** define verification steps and actions
- **Edges** define the connections between nodes  
- **Outcomes** determine which path to take based on results

## Flow Structure

A flow consists of two main components:

### Nodes Array

Each node represents a step in your verification process. Nodes have specific types and configurations that determine what happens at that step.

### Edges Array

Edges connect nodes together, defining the possible paths through your flow based on outcomes and conditions.

## Conversation node

Use the Conversation node to ask the user for information or guide them with an AI prompt.

### When to use

- Gather short pieces of information (name, intent, missing details)
- Provide instructions before a capture step (e.g., document scan)

### Core fields

- `type`: `conversation`
- `prompt`: string — the message shown to the user
- `transitions`: array of `{ id, condition }` to branch to another node

### Minimal examples

Linear prompt:

```json
{
  "id": "greet",
  "type": "conversation",
  "prompt": "Hello! What's your name?",
  "transitions": [{ "id": "t1", "condition": "true" }]
}
```

Branching based on a captured variable (example condition, evaluated by your flow engine):

```json
{
  "id": "consent",
  "type": "conversation",
  "prompt": "Do you agree to continue?",
  "transitions": [
    { "id": "ok", "condition": "answer == 'yes'" },
    { "id": "exit", "condition": "answer != 'yes'" }
  ]
}
```

Link to full schema: see API Reference → `FSConversationNode`.

## Using Custom Flows

Include your custom flow in the session creation request:

<CodeGroup>

```typescript {{ title: 'TypeScript' }}
const session = await client.sessions.create({
  clientReferenceId: 'user-123',
  metadata: { userId: '123' },
  flow: myCustomFlow,
  // Don't include modules when using custom flows
})
```

```javascript {{ title: 'JavaScript' }}
const session = await client.sessions.create({
  clientReferenceId: 'user-123',
  metadata: { userId: '123' },
  flow: myCustomFlow,
  // Don't include modules when using custom flows
})
```

</CodeGroup>

## Best Practices

- Always start with a START node and end with an END node
- Ensure all possible outcome paths are connected
- Test flows thoroughly with different scenarios
- Use meaningful node IDs for easier debugging
- Consider user experience when designing conditional paths

<Note>
  Custom flows give you powerful control over the verification process, but with that comes responsibility. Make sure to test all possible paths and edge cases to ensure a smooth user experience.
</Note>
