## Overview {{ anchor: false }}

Flows give you complete control over the verification process using a node-graph system where:

- **Nodes** define verification steps and actions
- **Edges** define the connections between nodes  
- **Outcomes** determine which path to take based on results

## Flow Structure

A flow consists of two main components:

### Nodes Array

Each node represents a step in your verification process. Nodes have specific types and configurations that determine what happens at that step.

### Edges Array

Edges connect nodes together, defining the possible paths through your flow based on outcomes and conditions.

## Available Node Types

FaceSign supports 11 different node types for building flows:

## Conversation node

Use the Conversation node to ask the user for information or guide them with an AI prompt.

### When to use

- Gather short pieces of information (name, intent, missing details)
- Provide instructions before a capture step (e.g., document scan)

### Core fields

- `type`: `conversation`
- `prompt`: string — the message shown to the user
- `transitions`: array of `{ id, condition }` to branch to another node (at least one required)
- `doesNotRequireReply`: boolean (optional) — set to true if prompt doesn't need user response

### Minimal examples

Linear prompt:

```json
{
  "id": "greet",
  "type": "conversation",
  "prompt": "Hello! What's your name?",
  "transitions": [
    { "id": "next", "condition": "true" }
  ]
}
```

Branching based on a condition:

```json
{
  "id": "consent",
  "type": "conversation",
  "prompt": "Do you agree to continue?",
  "transitions": [
    { "id": "yes", "condition": "answer == 'yes'" },
    { "id": "no", "condition": "answer != 'yes'" }
  ]
}
```

Link to full schema: see API Reference → `FSConversationNode`.

## Liveness detection node

Detect whether a real person is present before proceeding.

### Core fields

- `type`: `liveness_detection`
- `outcomes`: map outcome → next node id (e.g., `livenessDetected`, `deepfakeDetected`, `noFace`)

### Minimal example

```json
{
  "id": "live",
  "type": "liveness_detection",
  "outcomes": {
    "livenessDetected": "next",
    "deepfakeDetected": "end",
    "noFace": "end"
  }
}
```

See API Reference → `FSLivenessDetectionNode` for full schema.

## Document scan node

Scan and extract data from an ID document.

### Core fields

- `type`: `document_scan`
- `scanningMode`: `SINGLE_SIDE` | `MULTI_SIDE` | `BARCODE`
- `allowedDocumentTypes`: array of `FSDocumentType`
- `outcomes`: map of outcome → next node id

### Minimal example

```json
{
  "id": "doc",
  "type": "document_scan",
  "scanningMode": "SINGLE_SIDE",
  "allowedDocumentTypes": ["MRTD_TYPE_PASSPORT"],
  "outcomes": { "scanSuccess": "end", "userCancelled": "end", "scanTimeout": "end" }
}
```

See API Reference → `FSDocumentScanNode` for full schema.

## Face scan node

Capture a user's face image with optional liveness checks and face matching.

### Core fields

- `type`: `face_scan` (required)
- `mode`: `"capture"` or `"compare"` (required) — capture a new face image, or compare against reference
- `outcomes`: map of outcome → next node id (`passed`, `notPassed`, `cancelled`, `error`)
- `captureInstructions`: string (optional) — custom instructions shown to user
- `requireLiveness`: boolean (optional) — require liveness verification
- `referenceImageKey`: string (optional) — key for reference image to match against (for compare mode)
- `referenceImageSource`: `"session"`, `"providedData"`, or `"url"` (optional)
- `similarityThreshold`: number (optional) — similarity threshold for face matching, 0-1 (for compare mode)
- `captureDelay`: number (optional) — delay before capture in milliseconds (default: 3000)
- `qualityThreshold`: number (optional) — minimum quality threshold (default: 0.7)
- `enableSound`: boolean (optional) — enable audio feedback (default: true)
- `enableHaptics`: boolean (optional) — enable haptic feedback (default: true)

### Minimal example (capture mode)

```json
{
  "id": "face",
  "type": "face_scan",
  "mode": "capture",
  "outcomes": {
    "passed": "end",
    "notPassed": "retry",
    "cancelled": "end",
    "error": "end"
  },
  "requireLiveness": true
}
```

### Compare mode example

```json
{
  "id": "face_match",
  "type": "face_scan",
  "mode": "compare",
  "referenceImageSource": "session",
  "referenceImageKey": "idCardPhoto",
  "similarityThreshold": 0.85,
  "outcomes": {
    "passed": "verified",
    "notPassed": "failed",
    "cancelled": "end",
    "error": "end"
  }
}
```

See API Reference → `FSFaceScanNode` for full schema.

## Data validation node

Validate a field and branch based on result.

### Core fields

- `type`: `data_validation`
- `validation`: `{ field, action, value? }`
- `transitions`: array of condition-based transitions

### Minimal example

```json
{
  "id": "checkAge",
  "type": "data_validation",
  "validation": { "field": "age", "action": ">=", "value": "18" },
  "transitions": [
    { "id": "ok", "condition": "age >= 18" },
    { "id": "fail", "condition": "age < 18" }
  ]
}
```

See API Reference → `FSDataValidationNode` for full schema.

## Two factor node

Send and verify an OTP via email and/or SMS.

### Core fields

- `type`: `two_factor`
- `channels`: array of `"email"` and/or `"sms"`
- `contactSource`: `"session_data"` | `"module_settings"` | `"recognition_match"`
- `outcomes`: map of outcome → next node id (`verified`, `delivery_failed`, `failed_unverified`, `cancelled`, `error`)

### Contact configuration

- `staticEmail`: string (optional) — static email address to use
- `staticPhone`: string (optional) — static phone number to use

### Templates

- `emailTemplate`: string (optional) — custom email template with variables like `{{code}}`, `{{userName}}`
- `smsTemplate`: string (optional) — custom SMS template with variables

### OTP settings

- `otpLength`: number (optional) — OTP length, 4-8 digits (default: 6)
- `expirySeconds`: number (optional) — OTP expiry time in seconds (default: 300)
- `maxAttempts`: number (optional) — max verification attempts (default: 3)
- `resendAfterSeconds`: number (optional) — minimum delay before allowing resend

### UI settings

- `showUI`: boolean (optional) — show on-screen notification toast (default: true)

### Test mode

- `testMode`: object (optional) — test configuration with `enabled`, `email`, `phone`

### Minimal example

```json
{
  "id": "verifyOtp",
  "type": "two_factor",
  "channels": ["email"],
  "contactSource": "session_data",
  "outcomes": {
    "verified": "end",
    "delivery_failed": "error",
    "failed_unverified": "retry",
    "cancelled": "end",
    "error": "end"
  },
  "otpLength": 6,
  "expirySeconds": 300,
  "maxAttempts": 3
}
```

See API Reference → `FSTwoFactorNode` for full schema.

## Recognition node

Search for a user face in your database (1:N) and branch by outcome.

### Core fields

- `type`: `recognition`
- `outcomes`: map of outcome → next node id (e.g., `recognized`, `newUser`, `noFace`)

### Minimal example

```json
{
  "id": "recognize",
  "type": "recognition",
  "outcomes": { "recognized": "next", "newUser": "enroll", "noFace": "end" }
}
```

See API Reference → `FSRecognitionNode` for full schema.

## Using Custom Flows

Include your custom flow in the session creation request:

<CodeGroup>

```typescript {{ title: 'TypeScript' }}
const session = await client.sessions.create({
  clientReferenceId: 'user-123',
  metadata: { userId: '123' },
  flow: myCustomFlow,
  // Don't include modules when using custom flows
})
```

```javascript {{ title: 'JavaScript' }}
const session = await client.sessions.create({
  clientReferenceId: 'user-123',
  metadata: { userId: '123' },
  flow: myCustomFlow,
  // Don't include modules when using custom flows
})
```

## Best Practices

- Always start with a START node and end with an END node
- Ensure all possible outcome paths are connected
- Test flows thoroughly with different scenarios
- Use meaningful node IDs for easier debugging
- Consider user experience when designing conditional paths
