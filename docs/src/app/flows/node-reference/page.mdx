## Overview

FaceSign flows are composed of nodes connected by edges. Each node represents a specific verification step or logical operation. This reference provides complete documentation for all available node types.

## Verification Nodes

### CONVERSATION Node

**Purpose**: AI-powered conversational interaction with the user. Can ask questions, provide information, or gather data.

<SimpleCodeBlock
  title="CONVERSATION Node Structure"
  language="typescript"
  code={`interface FSConversationNode {
  id: string
  type: "conversation"
  prompt: string                           // The message/question to present
  transitions: FSNodeTransition[]          // Conditional routing based on response
  doesNotRequireReply?: boolean           // If true, continues without waiting for response
}

interface FSNodeTransition {
  id: string
  targetNodeId: string  // Next node to execute
  condition: string     // JavaScript expression evaluated against response
}`}
/>

**Example Usage:**
<SimpleCodeBlock
  language="json"
  code={`{
  "id": "ask_name",
  "type": "conversation",
  "prompt": "Hello! What's your full name?",
  "transitions": [
    {
      "id": "has_name",
      "targetNodeId": "verify_email",
      "condition": "response.length > 0"
    },
    {
      "id": "no_name",
      "targetNodeId": "ask_name_again",
      "condition": "response.length === 0"
    }
  ]
}`}
/>

## Connecting Nodes with Edges

Nodes are connected using edges to define the flow path:

<SimpleCodeBlock

  code={`interface FSEdge {
  id: string
  source: string      // Source node ID
  target: string      // Target node ID

}`}
/>

<SimpleCodeBlock

## Transitions and Conditions

Some nodes support conditional transitions based on user input or verification results:

### Condition Syntax

Conditions are JavaScript expressions evaluated at runtime:

- `true` - Always proceed
- `response.length > 0` - Check response has content
- `age >= 18` - Numeric comparison
- `country === "US"` - String comparison
- `email.includes("@company.com")` - String contains

### Transition Priority

Transitions are evaluated in order. The first matching condition determines the next node.

## Common Flow Patterns

### Basic Identity Verification
```
START → ENTER_EMAIL → DOCUMENT_SCAN → LIVENESS_DETECTION → END
```

### Enhanced KYC Flow
```
START → ENTER_EMAIL → DOCUMENT_SCAN → FACE_SCAN → TWO_FACTOR → END
```

### Conditional Verification
```
START → DATA_VALIDATION → (high_risk) → DOCUMENT_SCAN → LIVENESS → END
                        → (low_risk) → EMAIL → END
```

### Returning User Flow
```
START → RECOGNITION → (recognized) → TWO_FACTOR → END
                   → (new_user) → DOCUMENT_SCAN → REGISTER → END
```

## Error Handling

Each node type has specific failure outcomes. Always handle:

- User cancellation
- Timeouts
- Technical failures
- Validation failures
