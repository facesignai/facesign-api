# Error Handling

The FaceSign API uses conventional HTTP response codes to indicate the success or failure of an API request. Understanding these errors and implementing proper error handling is crucial for building a robust integration. {{ className: 'lead' }}

## HTTP status codes

FaceSign returns the following HTTP status codes:

<Properties>
  <Property name="200 OK">
    The request was successful.
  </Property>
  <Property name="201 Created">
    The resource was successfully created.
  </Property>
  <Property name="400 Bad Request">
    The request was invalid or cannot be served. Check the error message for details.
  </Property>
  <Property name="401 Unauthorized">
    The request requires authentication or the API key is invalid.
  </Property>
  <Property name="403 Forbidden">
    The API key doesn't have permissions to perform the request.
  </Property>
  <Property name="404 Not Found">
    The requested resource doesn't exist.
  </Property>
  <Property name="409 Conflict">
    The request conflicts with another request (perhaps using the same idempotency key).
  </Property>
  <Property name="429 Too Many Requests">
    Too many requests hit the API too quickly. We recommend implementing exponential backoff.
  </Property>
  <Property name="500 Internal Server Error">
    Something went wrong on FaceSign's end. These are rare.
  </Property>
</Properties>

## Error response format

All error responses follow a consistent format:

```json {{ title: 'Error response' }}
{
  "error": {
    "type": "validation_error",
    "message": "The 'clientReferenceId' field is required"
  }
}
```

### Error object properties

<Properties>
  <Property name="type" type="string">
    The type of error returned. See error types below.
  </Property>
  <Property name="message" type="string">
    A human-readable message providing more details about the error.
  </Property>
  <Property name="param" type="string">
    The parameter the error relates to if the error is parameter-specific.
  </Property>
  <Property name="code" type="string">
    A short string uniquely identifying the problem.
  </Property>
</Properties>

## Error types

<Properties>
  <Property name="authentication_error">
    Failure to properly authenticate in the request.
  </Property>
  <Property name="validation_error">
    Invalid request or failed validation.
  </Property>
  <Property name="not_found_error">
    Requested resource doesn't exist.
  </Property>
  <Property name="rate_limit_error">
    Too many requests hit the API too quickly.
  </Property>
  <Property name="server_error">
    Internal server error.
  </Property>
</Properties>

## Handling errors

Here's how to properly handle errors in your integration:

<CodeGroup title="Error handling examples">

```typescript {{ title: 'TypeScript' }}
import { FaceSign } from '@facesign/sdk';

const facesign = new FaceSign({
  apiKey: process.env.FACESIGN_API_KEY,
});

try {
  const session = await facesign.sessions.create({
    mode: 'redirect',
    success_url: 'https://example.com/success',
    cancel_url: 'https://example.com/cancel',
  });
} catch (error) {
  if (error.type === 'invalid_request_error') {
    // Handle invalid parameters
    console.error(`Invalid parameter: ${error.param}`);
    console.error(`Error message: ${error.message}`);
  } else if (error.type === 'authentication_error') {
    // Handle authentication errors
    console.error('Check your API key');
  } else if (error.statusCode === 429) {
    // Handle rate limiting
    console.error('Rate limited. Retry after:', error.headers['retry-after']);
  } else {
    // Handle other errors
    console.error('An unexpected error occurred:', error.message);
  }
}
```

    # Handle rate limiting
    print(f"Rate limited. Retry after: {e.headers.get('retry-after')}")

## Common errors and solutions

### Authentication errors

```json {{ title: 'Invalid API key' }}
{
  "error": {
    "type": "authentication_error",
    "message": "Invalid API key provided.",
    "code": "invalid_api_key"
  }
}
```

**Solution**: Check that you're using the correct API key and that it hasn't been revoked.

### Invalid request errors

```json {{ title: 'Missing required parameter' }}
{
  "error": {
    "type": "invalid_request_error",
    "message": "The 'success_url' parameter is required.",
    "param": "success_url",
    "code": "parameter_missing"
  }
}
```

**Solution**: Ensure all required parameters are included in your request.

### Rate limit errors

```json {{ title: 'Rate limit exceeded' }}
{
  "error": {
    "type": "rate_limit_error",
    "message": "Too many requests. Please retry after 60 seconds.",
    "code": "rate_limit_exceeded"
  }
}
```

**Solution**: Implement exponential backoff and respect the `Retry-After` header.

## Implementing retry logic

For transient errors and rate limiting, implement exponential backoff:

<CodeGroup title="Retry with exponential backoff">

```typescript {{ title: 'TypeScript' }}
async function createSessionWithRetry(params: any, maxRetries = 3) {
  let lastError;
  
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await facesign.sessions.create(params);
    } catch (error) {
      lastError = error;
      
      // Don't retry client errors (4xx) except rate limits
      if (error.statusCode >= 400 && error.statusCode < 500 && error.statusCode !== 429) {
        throw error;
      }
      
      // Calculate delay with exponential backoff
      const delay = Math.min(1000 * Math.pow(2, i), 10000);
      
      // Use Retry-After header if available
      if (error.headers && error.headers['retry-after']) {
        const retryAfter = parseInt(error.headers['retry-after']) * 1000;
        await new Promise(resolve => setTimeout(resolve, retryAfter));
      } else {
        await new Promise(resolve => setTimeout(resolve, delay));
      }
    }
  }
  
  throw lastError;
}
```

```python {{ title: 'Python' }}
import time
import random

def create_session_with_retry(params, max_retries=3):
    last_error = None
    
    for i in range(max_retries):
        try:
            return facesign.Session.create(**params)
        except Exception as error:
            last_error = error
            
            # Don't retry client errors (4xx) except rate limits
            if hasattr(error, 'http_status'):
                if 400 <= error.http_status < 500 and error.http_status != 429:
                    raise
            
            # Calculate delay with exponential backoff
            delay = min(1 * (2 ** i), 10)
            
            # Use Retry-After header if available
            if hasattr(error, 'headers') and 'retry-after' in error.headers:
                time.sleep(int(error.headers['retry-after']))
            else:
                # Add jitter to prevent thundering herd
                time.sleep(delay + random.uniform(0, 0.1))
    
    raise last_error
```

## Idempotency

To safely retry requests without accidentally performing the same operation twice, use idempotency keys:

<CodeGroup title="Using idempotency keys">

```typescript {{ title: 'TypeScript' }}
const session = await facesign.sessions.create({
  mode: 'redirect',
  success_url: 'https://example.com/success',
  cancel_url: 'https://example.com/cancel',
}, {
  idempotencyKey: 'unique-key-for-this-request',
});
```

```python {{ title: 'Python' }}
session = facesign.Session.create(
    mode='redirect',
    success_url='https://example.com/success',
    cancel_url='https://example.com/cancel',
    idempotency_key='unique-key-for-this-request'
)
```

```bash {{ title: 'cURL' }}
curl https://api.facesign.ai/v1/sessions \
  -H "Authorization: Bearer sk_test_..." \
  -H "Idempotency-Key: unique-key-for-this-request" \
  -d mode=redirect \
  -d success_url="https://example.com/success" \
  -d cancel_url="https://example.com/cancel"
```

## Best practices

1. **Always handle errors gracefully** - Don't let API errors crash your application
2. **Log errors for debugging** - Include request IDs for easier troubleshooting
3. **Implement retry logic** - Use exponential backoff for transient errors
4. **Respect rate limits** - Monitor your usage and implement proper throttling
5. **Use idempotency keys** - Prevent duplicate operations when retrying
6. **Show user-friendly messages** - Don't expose technical error details to end users

## Getting help

If you encounter persistent errors:

1. Check the [API status page](https://status.facesign.ai) for any ongoing issues
2. Review your request parameters against the API documentation
3. Contact support with the request ID from the error response
