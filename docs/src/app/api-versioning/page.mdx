## Version Header

All API requests should include the version header to ensure consistent behavior:

<SimpleCodeBlock
  title="Setting API Version"
  defaultLanguage="typescript"
  languageSwitcher="tabs"
  codeExamples={{
    typescript: `import { Client } from '@facesignai/api'

const client = new Client({
  auth: process.env.FACESIGN_API_KEY,
  // Version is set automatically to latest stable
  // Override if needed:
  headers: {
    'Facesign-Version': '2024-12-18'
  }
})`,
    curl: `curl https://api.dev.facesign.ai/sessions \\
  -H "Authorization: Bearer YOUR_API_KEY" \\
  -H "Facesign-Version: 2024-12-18"`,
    python: `import facesignai

client = facesignai.Client(
    auth=os.environ.get('FACESIGN_API_KEY'),
    headers={
        'Facesign-Version': '2024-12-18'
    }
)`
  }}

## Backward Compatibility

### Compatibility Guarantees

We guarantee backward compatibility for:

- ✅ All non-deprecated endpoints
- ✅ Request/response field names
- ✅ Required vs optional field status
- ✅ Authentication methods
- ✅ Error response formats
- ✅ Webhook payload structure

### Non-Breaking Changes

These changes are considered backward compatible:

- Adding new optional fields to requests
- Adding new fields to responses
- Adding new endpoints
- Adding new node types
- Adding new enum values
- Increasing rate limits

### Breaking Changes

These require a new API version:

- Removing or renaming endpoints
- Removing or renaming fields
- Changing field types
- Changing required/optional status
- Modifying authentication
- Changing error codes

response = client.session.list()

### Version Announcements

2. **Dashboard Alerts**: Shown in the FaceSign dashboard
