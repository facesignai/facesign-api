## When to Use Each Environment

### Use Sandbox (Flow Designer) for:

<VStack align="start" gap={3} my={4} pl={4}>
  <Text>✓ **Designing flows**: Visual interface for creating verification workflows</Text>
  <Text>✓ **Testing logic**: Validate flow behavior before production</Text>
  <Text>✓ **Creating demos**: Show stakeholders how verification works</Text>
  <Text>✓ **Training staff**: Familiarize team with FaceSign capabilities</Text>
  <Text>✓ **Rapid prototyping**: Quickly iterate on verification flows</Text>
</VStack>

### Use Production API for:

<VStack align="start" gap={3} my={4} pl={4}>
  <Text>✓ **Live verification**: Process real user identities</Text>
  <Text>✓ **User onboarding**: Verify new customers</Text>
  <Text>✓ **Ongoing authentication**: Re-verify existing users</Text>
  <Text>✓ **Compliance requirements**: Meet KYC/AML obligations</Text>
  <Text>✓ **Data sovereignty**: Keep data in your jurisdiction</Text>
</VStack>

## API Differences

While both environments use the same API structure, there are key differences:

### Base URLs
```javascript
// Sandbox
const sandboxClient = new Client({
  auth: 'sk_test_...',
  serverUrl: 'https://api.dev.facesign.ai'
})

// Production
const productionClient = new Client({
  auth: 'sk_live_...',
  serverUrl: 'https://api.facesign.ai'
})
```

### Webhook Validation

### Rate Limits

- **Sandbox**: Lower rate limits suitable for testing
- **Production**: Higher rate limits based on your plan

## Security Considerations

### Sandbox Security
- Use only test API keys (`sk_test_...`)
- No real PII should ever be transmitted
- Sessions auto-expire after testing
- Limited retention of test data

### Production Security
- Use production API keys (`sk_live_...`)
- Implement proper key rotation
- Store keys securely (environment variables, secrets management)
- Audit all access and operations
- Implement webhook signature validation

## Migration Path

<Box my={6}>
  <Heading size="md" mb={4}>From Sandbox to Production</Heading>

  1. **Design & Test** in Sandbox with sample data
  2. **Export** flow configuration (BETA feature)
  3. **Implement** in your application using the SDK
  4. **Configure** production API credentials
  5. **Deploy** to your infrastructure
  6. **Monitor** real verifications
</Box>

## Best Practices

### Sandbox Best Practices
- Use realistic test scenarios
- Test edge cases and error conditions
- Document your test flows
- Share demo links with stakeholders
- Clean up test sessions regularly

### Production Best Practices
- Implement comprehensive error handling
- Set up monitoring and alerting
- Maintain audit logs
- Regular security reviews
- Plan for scaling
