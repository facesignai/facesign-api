# Sessions

Sessions are the core resource in FaceSign. Create a session to initiate an identity verification flow, then provide the client secret to your end user to begin verification. {{ className: 'lead' }}

## Overview {{ anchor: false }}

A session represents a single identity verification journey. Each session contains:

- A unique ID for tracking
- Settings that define the verification flow
- Status tracking the user's progress
- A report with verification results (when complete)

Sessions use a **node-based flow system** where you define verification steps as nodes (like liveness detection, document scanning) connected by edges that determine the user's path through verification.

---

## Create a session

Create a new verification session by providing a flow definition. The flow contains nodes (verification steps) and edges (connections between steps).

<Row>
  <Col>

### Required parameters

<ParametersSection>
  <ParameterField name="flow" type="object" required>
    Node-based flow definition containing:
    - `nodes` - Array of FSNode objects (START, END, and verification steps)
    - `edges` - Array of edge objects connecting nodes

    See [Custom Flows](/flows) for complete node type documentation.
  </ParameterField>
</ParametersSection>

### Optional parameters

<ParametersSection>
  <ParameterField name="clientReferenceId" type="string">
    Your internal reference ID for this verification (e.g., your user ID).
  </ParameterField>
  <ParameterField name="metadata" type="object">
    Custom key-value pairs attached to the session. Useful for storing additional context.
  </ParameterField>
  <ParameterField name="providedData" type="object">
    Pre-fill data for the session (name, email, phone, etc.). Useful when you already know some user information.
  </ParameterField>
  <ParameterField name="avatarId" type="string">
    ID of the AI avatar to use for conversation nodes. See [Avatars](/avatars) for available options.
  </ParameterField>
  <ParameterField name="langs" type="array">
    Array of language codes supported in this session (e.g., `["en", "es", "fr"]`). User can switch between these languages.
  </ParameterField>
  <ParameterField name="defaultLang" type="string">
    Default language code (e.g., `"en"`). Defaults to English if not specified.
  </ParameterField>
  <ParameterField name="zone" type="string">
    Data residency zone: `"es"` (Spain) or `"eu"` (Europe). Determines where session data is stored.
  </ParameterField>
  <ParameterField name="customization" type="object">
    UI customization options for permissions page and controls. See [Customization](/customization) for details.
  </ParameterField>
  <ParameterField name="videoAIAnalysisEnabled" type="boolean">
    Enable AI analysis of user video recordings. Provides behavioral insights and fraud detection signals.
  </ParameterField>
</ParametersSection>

### Returns

Returns a session object with an embedded client secret. Provide the `clientSecret.url` to your end user to begin verification.

## Retrieve a session

Retrieve a session by its ID to check status and access verification results.

<Row>
  <Col>

### Path parameters

<ParametersSection>
  <ParameterField name="sessionId" type="string" required>
    The unique session identifier returned when creating a session.
  </ParameterField>
</ParametersSection>

### Returns

Returns a session object if a valid session ID was provided. The response includes the complete session state and report (if verification is complete).

  </Col>
  <Col sticky>

## List all sessions

Retrieve a paginated list of all sessions. Useful for building admin dashboards or syncing verification status.

<Row>
  <Col>

### Query parameters

<ParametersSection>
  <ParameterField name="limit" type="integer">
    Maximum number of sessions to return (1-100). Defaults to 10.
  </ParameterField>
  <ParameterField name="startingAfter" type="string">
    Session ID to start pagination after. Use for fetching the next page.
  </ParameterField>
  <ParameterField name="status" type="string">
    Filter by status: `requiresInput`, `processing`, `complete`, or `canceled`.
  </ParameterField>
  <ParameterField name="clientReferenceId" type="string">
    Filter by your internal reference ID.
  </ParameterField>
</ParametersSection>

### Returns

Returns an object with a `sessions` array and pagination metadata (`hasMore`, `lastId`).

  </Col>
  <Col sticky>

<TabbedCodeBlock
  defaultLanguage="curl"
  codeExamples={{
    curl: `curl "https://api.dev.facesign.ai/sessions?limit=10&status=complete" \\
  -H "Authorization: Bearer sk_test_..."`,
    javascript: `const { sessions, hasMore, lastId } = await client.session.list({
  limit: 10,
  status: 'complete'
})

// Fetch next page
if (hasMore) {
  const nextPage = await client.session.list({
    limit: 10,
    startingAfter: lastId
  })
}`,
    python: `response = client.session.list(
    limit=10,
    status='complete'
)

sessions = response['sessions']
has_more = response['hasMore']
last_id = response['lastId']

# Fetch next page
if has_more:
    next_page = client.session.list(
        limit=10,
        starting_after=last_id
    )`
  }}

## Session statuses

Sessions move through different statuses as users progress through verification:

<ParametersSection>
  <ParameterField name="requiresInput" type="status">
    Session created but user hasn't opened the verification URL yet.
  </ParameterField>
  <ParameterField name="processing" type="status">
    User started verification and is actively going through the flow.
  </ParameterField>
  <ParameterField name="complete" type="status">
    User completed all steps and reached an END node. Verification data is available in the report.
  </ParameterField>
  <ParameterField name="canceled" type="status">
    Session was canceled (either by user closing the tab or via API).
  </ParameterField>
</ParametersSection>

<Note>
  Sessions remain accessible indefinitely regardless of status. You can retrieve completed sessions at any time to access their verification reports.
</Note>
