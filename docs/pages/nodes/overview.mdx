## Node Structure

All nodes share a common base structure:

```typescript
interface FSNodeBase {
  id: string        // Unique identifier within the flow
  type: FSNodeType  // The type of node
}
```

Each node type extends this base with specific properties and configurations.

## Building Flows

Flows are built by connecting nodes with edges:

```typescript
const flow = {
  nodes: [
    { id: 'start', type: FSNodeType.START },
    { 
      id: 'greeting', 
      type: FSNodeType.CONVERSATION,
      prompt: 'Welcome! How can I help you?',
      transitions: []
    },
    { id: 'end', type: FSNodeType.END }
  ],
  edges: [
    { id: 'e1', source: 'start', target: 'greeting' },
    { id: 'e2', source: 'greeting', target: 'end' }
  ]
}
```

## Node Categories

### 1. Control Flow Nodes
These nodes control the flow of the verification process:
- **Start**: Entry point (required)
- **End**: Exit point (required)
- **Conversation**: Interactive AI dialogue
- **Data Validation**: Conditional branching

### 2. Authentication Nodes
These nodes verify user identity through various methods:
- **Two-Factor**: Send and verify codes via email/SMS
- **Enter Email**: Collect and validate email addresses

### 3. Biometric Nodes
These nodes use facial biometrics for verification:
- **Face Scan**: Capture face images with 1:1 matching
- **Recognition**: 1:N facial recognition against a database
- **Liveness Detection**: Ensure a real person is present

### 4. Document Nodes
These nodes handle document verification:
- **Document Scan**: Capture and extract data from IDs and passports

## Outcomes and Transitions

Most nodes have multiple possible outcomes that determine the next step:

```typescript
// Example: Liveness Detection Node
{
  id: 'liveness',
  type: FSNodeType.LIVENESS_DETECTION,
  outcomes: {
    livenessDetected: 'continue',    // Success path
    deepfakeDetected: 'failed',       // Failure path
    noFace: 'retry'                   // Retry path
  }
}
```

## Best Practices

1. **Always start with a Start node** - Every flow must have exactly one Start node
2. **End with an End node** - Ensure all paths lead to an End node
3. **Handle all outcomes** - Define transitions for every possible node outcome
4. **Keep flows simple** - Complex flows are harder to maintain and debug
5. **Test edge cases** - Consider what happens when verification fails

## Example: Multi-Step Verification

Here's an example flow combining multiple node types:

```typescript
{
  nodes: [
    { id: 'start', type: FSNodeType.START },
    
    // Collect email
    {
      id: 'email',
      type: FSNodeType.ENTER_EMAIL,
      outcomes: {
        emailEntered: 'face',
        canceled: 'end'
      }
    },
    
    // Face scan
    {
      id: 'face',
      type: FSNodeType.FACE_SCAN,
      mode: 'capture',
      outcomes: {
        captured: 'liveness',
        noFace: 'face-retry',
        error: 'end'
      }
    },
    
    // Liveness check
    {
      id: 'liveness',
      type: FSNodeType.LIVENESS_DETECTION,
      outcomes: {
        livenessDetected: '2fa',
        deepfakeDetected: 'end',
        noFace: 'face'
      }
    },
    
    // Two-factor authentication
    {
      id: '2fa',
      type: FSNodeType.TWO_FACTOR,
      channels: ['email'],
      contactSource: 'session_data',
      outcomes: {
        verified: 'success',
        failed_unverified: 'end',
        delivery_failed: 'end'
      }
    },
    
    // Success message
    {
      id: 'success',
      type: FSNodeType.CONVERSATION,
      prompt: 'Verification complete! Welcome aboard.',
      transitions: [{ id: 't1', condition: 'true' }]
    },
    
    { id: 'end', type: FSNodeType.END }
  ],
  
  edges: [
    { id: 'e1', source: 'start', target: 'email' },
    // ... additional edges connecting all outcomes
  ]
}
```
